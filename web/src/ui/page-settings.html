AI Agent

Connects to any OpenAI-compatible endpoint: a hosted provider, a gateway, or a model running on your own hardware. A hosted endpoint sends router names, addresses and network shape to that provider. A local one (Ollama, LM Studio, vLLM, LiteLLM) sends nothing outside your network. The AI Agent page appears once this is switched on and an endpoint and model are set.

The most the model may write in one reply, its reasoning included. A reasoning model that runs out writes nothing; raise it if answers come back cut off.
For an endpoint on your own network with a self-signed certificate. Press Test Connection: if the certificate is not trusted, it is shown with a Trust button that fills this in, then save. Only that exact certificate is accepted afterwards.
The assistant can only change things you are allowed to change yourself, and every change goes through the same checks, confirmation and audit trail as the forms. Turning this off lets it apply ordinary changes without asking. A change that could cut MikroDash off from the router is always put to you, whatever this is set to.
For what no page covers. Offered only to signed-in global administrators, and every command, even a read, is shown to you and runs only when you type the router's name. Raw commands skip MikroDash's own checks, read-back and undo, so leave this off unless you need it.

DNS tools

Each is off until you switch it on, and off it draws nothing and reads nothing.

Tick static entries on the DNS page to change their address list, forwarder or state, or remove them, in one job paced by the write limit; export the table as a RouterOS script or CSV.
Administrators: a Cache card on the DNS page that reads the resolver's cache when you press Read, searchable. The cache lists every name the network has looked up, so DNS read access alone does not open it. Nothing is read in the background.
Why a domain does or does not take its route: the static entry that catches it, what it resolved to, whether the address reached the list, and the mangle rule and route behind it.
In the fleet comparison, make the other routers' static entries match one router: add and change, and remove only if you choose to, after the counts are shown. Dynamic entries are never touched.
Administrators: keep FWD entries in step with a list of domains, pasted or fetched from a public URL, on the routers you pick. Only entries the list created are changed, and a fetch that comes back empty or under half its last size changes nothing on its own.
Monitoring and Wi-Fi
A Dashboard card for the address list your FWD entries feed: its size, the mangle rules that use it and the route they mark for, with an alert when that route stays down for three minutes. Only routers whose static entries feed the list are read, a few filtered prints a minute.
The list the card and the alert are about. Nothing is read until it is named.
Alert when a device you mark as watched is gone from Wi-Fi and from the router's ARP table for longer than its grace time. Those two are read on a router only while a device on it is watched.
Record each Wi-Fi client's signal and access point once a minute, so a client's name on Wifi Clients opens its history. Recording is switched on per router, on that page; only those routers have their Wi-Fi clients read while nobody has them open.
Colour each access point on the Wi-Fi map by its clients' average signal and list the clients below -75 dBm. Reads nothing new.
